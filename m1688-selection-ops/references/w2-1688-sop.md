## 🔁 单账号标准工作流 (v3 流程, 2026-08-01 强化)

> ⚠️ **2026-11-04 新增硬约束 (程序强制, 不再只是文档建议)**
> 旧流程靠「人自觉」把单任务控制在 15-30 词, 但采集器本身没有任何东西阻止你一次跑 174 词。
> 2026-11-04 实测: 同一账号一天连跑 90 词 → **触发 3 次真风控** (用户手动拖滑块 3 次)。
> 现在 `collect_m1688_v3_api.py` 内建 **风控守门四道闸门** (`v3_risk_guard.py`):
>
> | 闸门 | 规则 | 默认 | 覆盖 |
> |---|---|---|---|
> | 并发锁 | 同一账号同时只能有一个采集器 | 开 | `M1688_GUARD_ON=0` |
> | 轮次预算 | 每轮词数上限, 超过就**优雅停止** | **20 词** | `M1688_GUARD_ROUND_WORDS` |
> | 每日预算 | 每日词数上限, 超过就**优雅停止** | **60 词** | `M1688_GUARD_DAILY_WORDS` |
> | 产出熔断 | 每词产出连续下滑 (排序限流) 就停 | 3 笔/词 | `M1688_GUARD_MIN_YIELD` |
>
> 另外: 开跑前自动跑 **preflight** (`probe_preflight.py`, 1 个请求, 走 urllib 不用页面)。
> 返 `FAIL_SYS_USER_VALIDATE` / `_____tmd_____` / `访问被拒绝` = 风控 → **不要硬敲**,
> 走「风控四步流程」。
>
> **降载档** (被限流后):
> `$env:M1688_MAX_PAGES="2"; $env:M1688_KW_GAP_MIN="25"; $env:M1688_KW_GAP_MAX="45"; $env:M1688_LONG_PAUSE_CHANCE="0.25"`
>
> 单元测试: `python test_risk_guard.py` (16 项必须全过)

## 🛡️ 1688 风控 8 大应对 (来自实战, 7-31 复盘)

### 1. m.1688.com 移动版 (核心)
PC 端 `s.1688.com` 强风控 (滑块 + 行为分析 + 设备指纹)。移动版弱很多:
- 没 Cloudflare / reCAPTCHA
- 主要靠**账号 IP 频率**
- 同样脚本在 PC 端秒风控, 移动版能跑几百条

### 2. 真人账号 + 隔离 Chrome
- `tb966392038` (userid 2206668197833) — **唯一长期账号** (7-31 确认, 之前写的 2564316699 / tb753267369648 不存在)
- 隔离 `User Data_1688` 目录不和日常 Chrome 冲突
- 9223 debug 端口让 Playwright 复用真实 Chrome (不伪装成 bot)

### 3. URL goto 替代 fill+Enter (v2 关键)
- v1 用 `fill + press Enter` 触发 SPA navigation, 经常撞 "Execution context was destroyed"
- v2 直接 `goto("https://m.1688.com/offer_search/-6D7033.html?keywords=" + quote(kw, encoding='utf-8'))` 避开 navigation

### 4. 慢节奏 (单账号 SOP, 7-31 强化)
- sleep 12-18s 随机 + 每词回主页 4-5s
- 5-7 字复合词, 避开爆款 (钓鱼手套/钓鱼桶/助投器)
- 17-18 词后限流 (11-22 条/词), **不换账号** (单账号), 改等 2-4h 冷却

### 5. 硬风控立即停
- 检测 URL `_____tmd_____/punish?x5secdata=...` 立刻 `sys.exit(2)`
- 写 `1688_abort_signal.txt` 让其他 cron/任务感知
- 写 `_rejected_*.txt` / `_partial_*.xlsx` 保留已抓数据

### 6. 避免新 page 触发的 mtop 指纹缺失 (⭐ 关键, 8-01 强化)
- 新 page 缺 mtop 指纹, 易风控
- 解决: 重用 `ctx.pages[0]` (用户已搜过的页面)
- **首次跑前 user 必须在 9223 Chrome 手动搜一次 1688, 养 mtop 指纹** ← 8-01 强制
- **没养 mtop 直接跑 v6 = 第 1 词 100% abort** (实测 8-01)

### 7. harness 30min timeout 应对 (8-01 强化)
- v5 跑 42 词 = 30 分钟 harness 杀掉, _partial_save 没执行, 262 条全丢
- 解决: 每 5-10 词 auto-save partial (不只风控时存)
- 拆任务: 单任务 ≤ 25 词

### 8. 必跑跨表去重 (8-01 强化)
- v3/v4 鱼箱表跟 7-29 之前的表重了 198 行

### 10. GBK encoding 修复 (8-16, 强制)
- **症状**: 8-13 钓鱼椅 v5 任务末尾 GBK encoding 错误, 触发 `UnicodeEncodeError: 'gbk' codec can't encode character '\u2713'` (✓ 字符)
- **原因**: Windows GBK 不能编码 ✓ ✗ ⚠ ⏰ 💾 📊 📱 🚫 🔄 ❌ ✅ ✨ → ↻ ⤷ ⤶ 等 13 个 emoji
- **修复 (2 层保护)**:
  ```python
  import sys, io
  sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8', errors='replace', line_buffering=True)
  sys.stderr = sys.stdout

  def log(msg):
      safe = msg.replace("\u2713", "[OK]").replace("\u2717", "[X]").replace("\u26a0", "[!]")...  # 全 13 个 emoji 替换
      print(f"  {safe}", flush=True)
  ```
- **效果**: 8-16 钓鱼帽 v1 + 手机支架 v1 全跑完整, 不再因 ✓ 触发 traceback
- **必须**: 所有新脚本必带 2 层保护 (`collect_m1688_v2_*.py` 模板)
- **样板**: `collect_m1688_v2_diaomao_v1.py` + `collect_m1688_v2_phone_holder_v1.py`
